# CodeGuide Finance Tracker App Flow Document

## Onboarding and Sign-In/Sign-Up
When a new user first visits the application by navigating to the root URL, they land on a welcoming landing page. This page presents an overview of the finance tracker’s key benefits, along with prominent buttons for signing in or signing up. If the user chooses to create a new account, they can select between entering an email address and password or using a social login option such as Google or GitHub. Once the user submits their email, a verification code is sent to confirm their address, and they complete the sign-up by creating a strong password. Social login users grant permission through the provider’s OAuth flow before returning to the app as an authenticated user. After successful account creation, the application automatically redirects the user to the main dashboard.

Existing users can click the Sign In button and enter their credentials on the sign-in form, or use the same social login providers. Upon submission, the application validates credentials via Clerk and redirects successful logins to the dashboard. A “Forgot Password” link below the sign-in form allows users to request a password reset email. The email contains a secure link to a reset page where they choose a new password. After updating, the user is redirected back to the sign-in screen. Signing out is available at any time through the user menu in the top header, which logs the user out, clears the session, and returns them to the landing page.

## Main Dashboard or Home Page
Once signed in, the user lands on the dashboard page at `/dashboard`. A left-hand sidebar displays navigation links labeled Dashboard, Transactions, Budgets, Goals, Reports, AI Chat, and Settings. Above the main content area, a header shows the user’s name, profile avatar, a theme toggle (light/dark), and a sign-out button inside the user menu. The main content area consists of Card components showing financial summaries: total balance, monthly income, monthly expenses, and remaining budget. Below these, a Table preview lists the five most recent transactions. Quick-access buttons for adding a new transaction or budget appear above the table.

Users can click sidebar links to navigate to other sections. The sidebar remains persistent, offering seamless transitions. Breadcrumbs at the top of each page reflect the current location, so users always understand where they are in the application.

## Detailed Feature Flows and Page Transitions

### Transaction Management
When a user clicks the Transactions link, the app transitions to the `/transactions` page. This page displays a paginated table of all past income and expense entries, with columns for date, category, amount, type, and description. Filters at the top of the table allow the user to select date ranges or categories using dropdown selectors. To add a new entry, the user clicks the “Add Transaction” button, which opens a modal containing a transaction form built with shadcn/ui components. The user fills in required fields—date picker, amount input, category selector, type selector (income or expense), and optional description—and submits the form. The app sends a POST request to `/api/transactions`, where the data is validated by Zod and inserted into Supabase. Upon success, the modal closes, and the table refreshes automatically to include the new transaction. Users can edit or delete entries via inline action buttons. Editing loads the same form with pre-filled values, and deleting triggers a confirmation prompt before calling the DELETE endpoint.

### Budget Management
Selecting the Budgets link navigates to `/budgets`, where the user sees a list of budget rules they have created. Each budget card shows the category, total allocated amount, period (monthly or weekly), and current spent amount. A prominent “Create Budget” button opens a dedicated page at `/budgets/new` where the user specifies the category, amount, and period. Submitting this form triggers a POST request to `/api/budgets` and, once saved, returns the user to the budgets list, which updates to show their new budget. Users can click a budget card to view details and edit the settings on the page `/budgets/[id]` or delete the budget, which calls the DELETE API route.

### Financial Goals Tracking
When the user chooses Goals from the sidebar, they arrive at `/goals`. Goals are displayed in a progress-bar style list, showing each goal’s name, target amount, and current saved amount. To set a new goal, the user selects “Add Goal,” fills out a form on `/goals/new` with the goal name, target amount, and optional deadline, and submits. The application issues a POST request to `/api/goals` to insert the new goal record. The list then includes the new goal with its initial progress at zero. Clicking an existing goal opens `/goals/[id]`, allowing the user to update the current amount or delete the goal entirely.

### Interactive Reporting Dashboard
By clicking Reports, the user is taken to `/reports` where interactive charts and graphs illustrate financial trends. A line chart shows income versus expenses over time, a pie chart illustrates category breakdowns, and a bar chart compares budgets against actual spending. These charts are rendered inside Client Components that fetch data from GET endpoints such as `/api/transactions?range=monthly` and `/api/budgets`. Users can adjust date ranges or chart types via a toolbar above the charts. Changing a filter triggers a re-fetch of data and updates the visualizations in real time.

### AI-Powered Insights and Recommendations
The AI Chat section is accessible at `/ai-chat`. In this interface, users type questions or commands such as “Categorize my last five transactions” or “Suggest a monthly budget based on my spending history.” When the user submits a query, the app sends it to `/api/chat` which uses the Vercel AI SDK connected to the user’s financial data. The response appears in a chat window with recommended actions or automatically categorized transactions. Users can click suggested categories to apply them directly.

## Settings and Account Management
Under Settings at `/settings`, users can update their profile information, including display name, email, and password. They access form fields pre-populated with current values and save changes, which calls the PUT `/api/user` endpoint. A separate section in settings allows toggling notification preferences (daily summary emails or alert thresholds) and switching between light or dark mode. Theme changes apply instantly across the app and persist in user preferences. If the user has a subscription plan, the Billing tab shows current plan details, payment method on file, and next billing date. Users can update or delete payment methods via secure forms that integrate with a payment gateway API. After saving any settings, users remain on the Settings page and can use the sidebar to navigate back to the dashboard.

## Error States and Alternate Paths
If a user attempts to access any page without authentication, the app’s middleware detects the missing session and redirects to the sign-in page. Invalid credentials during sign-in display a clear error message instructing the user to retry. Submitting incomplete or incorrect form data triggers inline validation messages next to the relevant fields. If a network error occurs while calling an API, a banner appears at the top of the page advising the user to check their connection and try again. Attempting to delete a transaction or budget prompts a confirmation dialog to prevent accidental loss. If an unauthorized API call is made (for example, tampering with another user’s resource), the server responds with a 403 error, and the frontend shows a “Permission denied” message. All modals and form overlays gracefully close on pressing the Escape key or clicking outside.

## Conclusion and Overall App Journey
From landing on the home page as a newcomer to signing up via email or social login, the user’s journey moves smoothly into the secure dashboard environment. They record income and expenses, establish budgets, set financial goals, and explore detailed reports—all through a clear sidebar navigation and responsive UI. AI chat recommendations and theme personalization enrich the experience, while robust error handling keeps the user informed and in control. In everyday use, the typical end goal is to review their financial health on the dashboard, add new transactions, adjust budgets, and consult reports to stay on track toward their goals. Through each step, the app maintains security, privacy, and ease of use, culminating in a complete personal finance management solution.
